# Chattodo 产品地图

Chattodo 是一款面向技术支持、售后、实施和交付团队的 AI 工单待办助手。它把日常群聊、报错截图、日志材料和处理结论组织成可持续跟进的工单待办，帮助团队更快记录问题、更清楚推进排查、更系统沉淀经验。

## 一句话定位

```text
截图取证 -> AI 识别 -> 创建/追加工单 -> 时间线跟进 -> 辅助排查 -> 结论沉淀 -> 知识归档
```

## 适合谁使用

- 技术支持：快速从客户群、报错截图、日志材料中整理问题上下文。
- 售后团队：持续跟踪客户问题，避免信息散落在聊天记录里。
- 实施 / 交付：按项目管理环境、账号、跟进记录和最终结论。
- 研发协同人员：把排查过程整理成更适合转研发、复盘或知识库沉淀的材料。

## 核心功能介绍

### 1. 问题捕获

用户可以通过全局快捷键快速截图。Windows 默认使用 `Alt+A`，macOS 默认使用 `Command+Shift+A`。

截图后可以框选关键区域，也可以添加文字和箭头标注。适合截取客户群消息、系统报错、后台页面、日志片段、监控告警等问题上下文。

当一次截图无法说明完整问题时，可以使用多图采集，把多张截图合并交给 AI 分析。

### 2. AI 工单识别

AI 会从截图中提取工单相关信息，包括：

- 问题标题
- 当前问题摘要
- 本次新增跟进内容
- 群聊名称
- 项目 / 客户信息
- 产品线
- 模块、问题类型、严重程度
- 证据和关键线索

识别结果可以保存为新工单，也可以追加到当前选中的工单中。

### 3. 工单待办面板

桌面浮动待办面板用于快速查看当前仍在处理的问题。

常用操作包括：

- 选择一个正在跟进的工单
- 取消当前选择
- 打开工单详情
- 快速完成工单
- 展开 / 收起待办列表
- 置顶面板
- 拖动调整位置

这个面板适合在日常处理客户消息时常驻桌面，减少在聊天工具、文档和表格之间来回切换。

### 4. 工单详情与时间线

工单详情侧栏用于维护一个问题的完整处理过程。

详情中可以查看和编辑：

- 标题
- 当前摘要
- 结构化字段
- 项目关联状态
- 环境入口
- 时间线记录
- 附件
- 最终结论

时间线用于记录每一次沟通、排查、截图、日志分析结果和结论变化。每条时间线都可以附加图片、日志、压缩包或其他文件。

### 5. 辅助排查

当一个问题进入排查阶段后，可以打开辅助排查能力。系统会结合当前摘要、时间线和已有材料，生成更清晰的排查建议。

辅助排查可以帮助回答：

- 当前问题最可能的方向是什么？
- 下一步应该检查哪些信息？
- 哪些线索值得优先确认？
- 是否有类似历史案例？
- 该如何整理给研发或客户？

### 6. 相似案例检索

系统可以根据当前工单内容生成检索 query，并搜索历史案例或知识库内容。

检索结果会被去重、排序和评分。高相关案例会展示匹配原因和可参考结论，帮助支持人员减少重复排查。

### 7. 日志分析 Agent

在时间线中输入 `/分析日志`，并附加日志、压缩包或截图，即可创建异步日志分析任务。

日志分析不会阻塞主界面。任务执行过程中会展示状态，完成后会自动生成分析结果卡片。

分析结果通常包括：

- 阶段总结
- 关键日志线索
- 可能原因
- 建议排查路径
- 发研发摘要
- 发客户摘要
- 经验回流摘要

### 8. 项目管理

项目管理用于维护客户项目主数据。

支持能力包括：

- 新建和编辑项目
- 导入项目清单
- 维护项目别名
- 维护项目等级
- 维护跟进开始日期和支持结束日期
- 标识项目是否过保
- 根据群聊名称自动关联工单

项目关联后，工单可以自动获得更完整的客户和项目上下文。

### 9. 环境与账号管理

环境管理用于维护项目相关系统、后台、测试环境或客户环境的访问入口。

支持：

- 全局环境
- 项目环境
- 环境访问地址
- 用户名和密码
- OTP 动态验证码
- 从二维码或剪贴板导入 OTP
- 在工单详情中快速打开环境和复制登录信息

这适合实施、交付和支持人员处理需要频繁登录不同客户环境的场景。

### 10. 功能点自动匹配

当工单中已有产品线和问题描述时，系统可以调用外部功能点接口，自动匹配对应功能点。

自动匹配不会覆盖用户手动填写的功能点。接口异常也不会阻断工单保存。

### 11. 结论沉淀与知识归档

问题处理完成后，可以在工单中维护最终结论，并保留相关附件。

满足归档条件的工单可以沉淀为知识库 Markdown 文档，包含：

- 工单元信息
- 问题背景
- 排查过程
- 关键证据
- 解决方案
- 附件材料
- 产品线标签

系统还可以按产品线生成 Wiki 索引，方便后续检索和复用。

### 12. 外部平台同步

系统支持通过脚本集成外部平台。

当本地工单发生创建、追加、更新、完成、删除或手动同步时，可以把标准事件 JSON 发送给外部脚本，由脚本负责对接公司内部工单系统、表格、Webhook 或其他平台。

同步结果可以回传 `external_id` 和 `external_url`，系统会保存绑定关系，方便后续继续同步。

## 快速使用指南

### 第一步：配置模型

在控制面板中配置模型供应商和 API Key。

常见任务包括：

- 截图分析：需要支持视觉能力的模型
- 日志分析：可使用视觉或文本模型，取决于材料类型
- 方案导出：可使用文本模型
- 上下文摘要：可使用文本模型

### 第二步：使用快捷键截图

按下截图快捷键，框选问题区域并确认。

如果需要强调重点，可以先添加文字或箭头标注，再提交给 AI 分析。

### 第三步：保存为工单

AI 分析完成后，检查识别结果。

- 如果这是一个新问题，保存为新工单。
- 如果这是已有问题的补充信息，先在浮动面板选中对应工单，再保存为追加记录。

### 第四步：在时间线中持续跟进

打开工单详情，持续记录：

- 客户反馈
- 排查过程
- 日志材料
- 截图证据
- 研发回复
- 阶段结论

每次新增内容都会进入时间线，形成完整处理记录。

### 第五步：使用辅助排查

当信息越来越多时，可以打开辅助排查或阶段总结，让 AI 帮助整理当前进展。

如果有日志材料，可以在时间线中使用 `/分析日志` 创建日志分析任务。

### 第六步：完成并归档

问题解决后，填写最终结论，完成工单。

后续可以把工单归档到知识库，作为类似问题的处理参考。

## 典型场景

### 场景一：客户群里出现报错

```text
客户发报错截图
-> 使用快捷键截图
-> AI 提取问题摘要和关键字段
-> 创建工单
-> 后续客户补充信息继续截图追加
-> 完成后沉淀结论
```

### 场景二：一个问题需要多轮排查

```text
创建工单
-> 在时间线记录每次排查
-> 上传日志和截图
-> 使用辅助排查生成下一步建议
-> 生成阶段总结发给研发
-> 解决后补充最终结论
```

### 场景三：需要登录客户环境

```text
维护项目环境和访问账号
-> 工单自动关联项目
-> 在工单详情中查看环境入口
-> 复制用户名、密码或 OTP
-> 登录环境排查问题
```

### 场景四：把处理经验变成知识库

```text
完成工单
-> 填写结论和关键证据
-> 系统生成知识库 Markdown
-> 复制附件到归档目录
-> 更新产品线 Wiki 索引
-> 后续相似案例检索可复用
```

## 与传统记录方式的区别

| 传统方式 | Chattodo |
| --- | --- |
| 问题散落在聊天记录、截图和表格中 | 一个问题形成一个可持续跟进的工单 |
| 手动复制粘贴整理字段 | AI 自动提取标题、摘要和结构化字段 |
| 排查过程容易断层 | 时间线持续记录每次跟进 |
| 日志和截图难以归档 | 附件跟随时间线保存 |
| 经验复用依赖人工记忆 | 相似案例检索和知识库归档 |
| 项目环境信息分散 | 项目、环境、账号和 OTP 统一管理 |

## 数据与安全说明

- 应用数据默认保存在本机 `~/.aica/` 目录下。
- API Key 保存在本地配置文件中，请不要把真实密钥提交到代码仓库。
- 截图、附件、反馈、知识库归档也保存在本地目录。
- 外部平台同步通过脚本集成实现，本地工单操作不会因为外部同步失败而中断。
- 如需接入公司内部系统，建议先用最小脚本验证事件格式，再逐步接入真实 API。
